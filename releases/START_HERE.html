共有サーバーを起動する

フォルダをWebサーバーへ置くだけでは、オンライン対戦は動きません。
全プレイヤーのワールドを動かすNode.jsプロセスを1つ常駐させ、そのプロセスへHTTPとWebSocketを転送してください。

この手順は https://2012r2.nishi.boats/~333/japan/ で公開する場合の例です。すでに使っているWebサーバーに合わせて設定します。既存データがある場合は更新前にバックアップし、以前のプロセスを止めてから更新してください。

1. Node.jsを確認する

SSHでZIPを展開した rakugaki-multiplayer フォルダへ移動し、以下を実行します。Node.js 22以降が必要です。サーバー本体とデータは、直接ファイルを配信する公開フォルダの外に置くことを勧めます。

node --version
npm ci --ignore-scripts
npm test

Node.jsがない、または対応バージョンが使えない場合は、そのホストの管理者にNode.jsの常駐サービスについて確認してください。

2. 共有ワールドを1プロセスだけ起動する

Linuxなどのシェルでは、最初は次のコマンドを前面で実行し、エラーがないことを確認します。

HOST=127.0.0.1 PORT=3000 BASE_PATH=/~333/japan DATA_DIR="$HOME/rakugaki-data" COOKIE_SECURE=1 npm start

このターミナルを閉じると停止することがあります。初期確認後は、ホスティングのプロセス管理やsystemdで常駐させてください。Linuxで簡易に常駐させる場合は、前面のサーバーをCtrl+Cで止めてから次を実行します。

nohup env HOST=127.0.0.1 PORT=3000 BASE_PATH=/~333/japan DATA_DIR="$HOME/rakugaki-data" COOKIE_SECURE=1 node server.cjs > server.log 2>&1 &

WindowsのPowerShellでは環境変数の指定方法が異なります。常駐にはホストのサービス管理機能を使ってください。

$env:HOST="127.0.0.1"
$env:PORT="3000"
$env:BASE_PATH="/~333/japan"
$env:DATA_DIR="$env:USERPROFILE\rakugaki-data"
$env:COOKIE_SECURE="1"
npm start

PM2などを使用する場合もインスタンス数は1にします。異なるコンテナやホストへ複製して負荷分散する構成には対応していません。データフォルダには実行中のロック server.lock が作られます。異常終了後にロックが残った場合は、古いプロセスが本当に停止していることを確認してから、そのロックだけを削除してください。

3. 公開URLをNode.jsへ転送する

SSHでNode.jsを起動できても、公開URLは自動でNode.jsへ切り替わりません。既存Webサーバーの管理権限がない場合は、ホスティング管理者に「/~333/japan/ 全体を 127.0.0.1:3000 へHTTPとWebSocket込みでリバースプロキシしたい」と依頼してください。

Nginxの場合は、既存のHTTPS用serverブロック内に次の設定を追加します。既存設定全体を置き換えるものではありません。設定検査後に再読み込みしてください。

location = /~333/japan {
    return 301 /~333/japan/;
}
location /~333/japan/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 120s;
    proxy_buffering off;
}

Apacheの場合は、mod_proxy / mod_proxy_http / WebSocketのプロキシ機能を有効にし、既存のHTTPS用VirtualHostへ設定します。通常はサーバー管理者の作業です。

ProxyPreserveHost On
ProxyPass        "/~333/japan/ws" "ws://127.0.0.1:3000/~333/japan/ws"
ProxyPassReverse "/~333/japan/ws" "ws://127.0.0.1:3000/~333/japan/ws"
ProxyPass        "/~333/japan/" "http://127.0.0.1:3000/~333/japan/"
ProxyPassReverse "/~333/japan/" "http://127.0.0.1:3000/~333/japan/"

別のWebサーバーでも必要な条件は同じです。APIだけでなくWebSocketも転送し、外側のHostヘッダーを維持します。前段がパスを取り除く構成でも、保持する構成でも、この修正版は対応します。

4. 公開先で共有接続を確認する

公開URLと同じ場所にある api/health がHTMLではなくJSONを返し、mode: "multiplayer"、worldId、build: "2026-10-28-shared-1" を含むことを確認します。この手順書を公開URLから開いている場合は、次のボタンで確認できます。

未確認

ゲームを強制再読み込みし、2つのタブで開いてください。左上の「共有ワールド」に同じIDが表示され、一方で出撃した絵がもう一方にも見えれば共有されています。HTTP確認が成功してもゲームが接続エラーの場合は、WebSocketの転送設定とサーバーログを確認してください。

この修正版は通常のURLでは単独ワールドを起動しません。接続できない場合はエラー表示で停止します。意図して単独プレイを使う場合だけ、URLに ?mode=solo を付けてください。
